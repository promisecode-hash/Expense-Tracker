# Expense Tracker - Project Structure Documentation

## Project Overview
This is a **Clean Architecture** ASP.NET Core 8 REST API for expense tracking with JWT authentication, category filtering, spending summaries, and Swagger documentation.

---

## Complete Project Structure

### 📁 **ExpenseTracker.Domain** (Core Business Layer)

#### Entities
- **User.cs**: User aggregate with username, email, password hash, and timestamps
- **Category.cs**: Expense categories created per user with color coding
- **Expense.cs**: Individual expense records linked to users and categories

#### Enums
- **ExpenseCategory.cs**: Predefined expense types (Food, Transportation, Utilities, etc.)

#### Exceptions
- **DomainExceptions.cs**: Custom domain exceptions
  - `ExpenseNotFoundException`
  - `CategoryNotFoundException`
  - `UserNotFoundException`
  - `InvalidExpenseException`

#### Interfaces
- **RepositoryInterfaces.cs**: Repository contracts
  - `IExpenseRepository`
  - `ICategoryRepository`
  - `IUserRepository`

---

### 📁 **ExpenseTracker.Application** (Business Logic Layer)

#### DTOs (Data Transfer Objects)
- **ExpenseDto.cs**: `ExpenseDto`, `CreateExpenseDto`, `UpdateExpenseDto`
- **CategoryDto.cs**: `CategoryDto`, `CreateCategoryDto`, `UpdateCategoryDto`
- **UserDto.cs**: `UserDto`, `RegisterUserDto`, `LoginDto`, `AuthResponseDto`
- **SummaryDto.cs**: `SpendingSummaryDto`, `CategorySpendingDto`

#### Interfaces
- **ServiceInterfaces.cs**:
  - `IExpenseService`: CRUD operations for expenses
  - `ICategoryService`: CRUD operations for categories
  - `IUserService`: User registration and login
  - `ISummaryService`: Spending analytics and summaries

- **SecurityInterfaces.cs**:
  - `ITokenService`: JWT token generation and validation
  - `IPasswordService`: Password hashing and verification

#### Services
- **ExpenseCategoryService.cs**: 
  - `ExpenseService`: Implements `IExpenseService`
  - `CategoryService`: Implements `ICategoryService`

- **UserService.cs**: 
  - `UserService`: Implements `IUserService`
  - Handles registration, login, password verification

- **SummaryService.cs**: 
  - `SummaryService`: Implements `ISummaryService`
  - Calculates spending totals, averages, and category breakdowns

#### Validators
- **ExpenseValidator.cs**: Fluent validation rules for expenses
- **CategoryValidator.cs**: Fluent validation rules for categories
- **UserValidator.cs**: Fluent validation rules for user registration/login

#### Mappings
- **MappingProfile.cs**: AutoMapper configuration for DTO ↔ Entity mapping

---

### 📁 **ExpenseTracker.Infrastructure** (Data Access & External Services)

#### Data
- **ExpenseTrackerDbContext.cs**:
  - EF Core DbContext with fluent API configuration
  - Relationships: User → Many Expenses, User → Many Categories
  - Indexes on frequently queried columns
  - Cascade delete policies

#### Repositories
- **RepositoryImplementations.cs**:
  - `ExpenseRepository`: CRUD + filtering by category/date range
  - `CategoryRepository`: CRUD operations
  - `UserRepository`: CRUD + lookup by email/username

#### Services
- **JwtTokenService.cs**: Implements `ITokenService`
  - Token generation with claims (UserId, Email, Username)
  - Token validation
  - Configurable expiration and signing

- **PasswordService.cs**: Implements `IPasswordService`
  - Secure password hashing with PBKDF2
  - Salted password verification
  - 10,000 iterations for security

#### Migrations
- Directory for EF Core migrations (generated by `dotnet ef migrations add`)

#### Configuration
- Directory for database-specific configurations

---

### 📁 **ExpenseTracker.Api** (Presentation Layer)

#### Controllers
- **ExpensesController.cs** (`/api/expenses`)
  - GET all expenses for user
  - GET expense by ID
  - POST create expense
  - PUT update expense
  - DELETE expense
  - GET filter by category
  - GET filter by date range

- **CategoriesController.cs** (`/api/categories`)
  - GET all user categories
  - GET category by ID
  - POST create category
  - PUT update category
  - DELETE category

- **AuthController.cs** (`/api/auth`)
  - POST register new user
  - POST login (returns JWT token)
  - GET profile (requires auth)

- **AnalyticsController.cs** (`/api/analytics`)
  - GET spending summary (date range)
  - GET category breakdown with percentages

#### Extensions
- **ServiceCollectionExtensions.cs**:
  - Registers all services, repositories, and interfaces
  - Configures DbContext with SQL Server
  - Sets up JWT authentication
  - Configures AutoMapper and FluentValidation
  - Configures CORS
  - Configures Swagger/OpenAPI

#### Middlewares
- **GlobalExceptionFilter.cs**: Global error handling filter

#### Configuration
- Directory for API-specific settings (appsettings.json structure)

#### Properties
- Directory for launchSettings.json and project metadata

---

### 📁 **ExpenseTracker.Tests** (Quality Assurance)

## Database Schema

### Users Table
```
Id (GUID, PK)
Username (string, unique)
Email (string, unique)
PasswordHash (string)
FirstName (string)
LastName (string)
CreatedAt (DateTime)
UpdatedAt (DateTime, nullable)
IsActive (bool)
```

### Categories Table
```
Id (GUID, PK)
Name (string)
Description (string)
Color (string)
UserId (GUID, FK)
CreatedAt (DateTime)
UpdatedAt (DateTime, nullable)
```

### Expenses Table
```
Id (GUID, PK)
Description (string)
Amount (decimal)
TransactionDate (DateTime)
CategoryId (GUID, FK)
UserId (GUID, FK)
Notes (string, nullable)
CreatedAt (DateTime)
UpdatedAt (DateTime, nullable)
```

## API Endpoints Summary

### Authentication
- `POST /api/auth/register` - Register new user
- `POST /api/auth/login` - Login and get JWT token
- `GET /api/auth/profile` - Get user profile (requires auth)

### Expenses
- `GET /api/expenses` - Get all user expenses
- `GET /api/expenses/{id}` - Get expense by ID
- `POST /api/expenses` - Create new expense
- `PUT /api/expenses/{id}` - Update expense
- `DELETE /api/expenses/{id}` - Delete expense
- `GET /api/expenses/filter/category/{categoryId}` - Filter by category
- `GET /api/expenses/filter/date-range?startDate=&endDate=` - Filter by date range

### Categories
- `GET /api/categories` - Get all user categories
- `GET /api/categories/{id}` - Get category by ID
- `POST /api/categories` - Create new category
- `PUT /api/categories/{id}` - Update category
- `DELETE /api/categories/{id}` - Delete category

### Analytics
- `GET /api/analytics/summary?startDate=&endDate=` - Get spending summary
- `GET /api/analytics/category-breakdown?startDate=&endDate=` - Get category breakdown
